# External integrations — pending, not deployed

## FEU Canvas

Connection decision (2026-10-24): the current Pockit School page has a read-only Canvas adapter and offline cache, but no account authentication, OAuth callback, protected session, or backend. `VITE_CANVAS_GATEWAY` is unset in the production build. The adapter must not be pointed directly at FEU Canvas; its current `protectedGateway` sends `credentials: include` but no Canvas token and would need a session transport update for the architecture below. FEU Tech confirms Canvas is its LMS, but public material does not establish that FEU Tech grants third-party developer keys or personal API tokens. Ask FEU Tech's Canvas administrators whether they will register and enable a scoped OAuth developer key for this app, and confirm the exact Canvas tenant URL and allowed read scopes. Do not ship a backend or collect credentials until that is confirmed.

Recommended architecture if approved: a separate `pockit-canvas` Cloudflare Worker on Workers Free, with an exact callback URL, state and PKCE if FEU's Canvas tenant supports it, and encrypted refresh tokens in a separate D1 database. Keep its client secret and encryption key as Worker secrets. The GitHub Pages app and `workers.dev` are different sites, so do not assume an iOS Home Screen app can use third-party session cookies. A safer first design is a short-lived, Canvas-independent gateway session held only in Pockit's memory after a one-time code exchange; reconnect after session expiry. Validate its iOS behavior and CSRF/replay protections before enabling live sync. Read only courses, assignments with submission state, announcements, calendar events and available grades. The browser receives only normalized academic data; a 401/403 clears connection status and offers reconnect while preserving the last offline cache. Manual sync stages the full snapshot and commits only on success. The existing ID namespace and merge behavior prevent duplicate imported records. This Worker should have no push or financial data bindings. Free-tier limits, especially 10 ms CPU and 50 subrequests per request, require testing with a real course count and bounded pagination; split sync into smaller authenticated requests if needed. No paid plan is required for a small personal connection, but feasibility is not yet verified.

Canvas documents personal API tokens as a testing mechanism and says applications used by multiple users must use OAuth. Do not ask for a token in Pockit, even as a fallback UI. Reference: [Canvas OAuth](https://developerdocs.instructure.com/services/canvas/oauth2/file.oauth), [developer keys](https://developerdocs.instructure.com/services/canvas/oauth2/file.developer_keys), [Workers Free limits](https://developers.cloudflare.com/workers/platform/limits/).

The public [FEU Canvas login](https://feu.instructure.com/) redirects to Microsoft sign-in via SAML. This establishes the interactive sign-in provider, not permission for third-party API access. FEU's developer-key policy, personal-token availability and CORS policy remain unverified without institutional confirmation. Do not ask for a password or paste a token into chat.

[Canvas OAuth documentation](https://sso.canvaslms.com/doc/api/file.oauth.html) describes institution-scoped developer keys. Preferred design: FEU-approved read-only OAuth scopes, state validation, exact callback allowlist and a protected backend keeping client secrets and refresh tokens off the public PWA. Never automate Microsoft login or forward its session cookies. Do not add a personal-token connection flow to Pockit; no public proxy and no token in URLs, exports, IndexedDB or service-worker caches.

The local gateway adapter now implements the client-side read/cache contract below, with mocked tests. The authenticated backend and real connection remain pending:

- Backend authorizes the user on every request, pins the upstream to FEU, allows only read endpoints and rejects redirects or pagination URLs to other origins.
- Read courses, assignments/submission states, announcements, events and available grades. Stable namespaced IDs include institution, resource type and Canvas ID. Imported items remain read-only.
- Follow opaque [Canvas pagination links](https://developerdocs.instructure.com/services/canvas/basics/file.pagination) subject to origin/path validation, a visited-URL set and page limits. Do not assume the first page is complete.
- Manual sync uses one in-flight operation, stages all pages, validates the payload, and atomically merges cache on success. A failed/partial fetch must not erase cache or advance last-success time. Course filtering is local until a complete scoped refresh succeeds.
- Distinguish 401/expired credentials, 403/permission failure, 429/throttling, network/offline and server errors. Honor Retry-After and stop bounded retries. Avoid logging upstream bodies or credentials.
- Persist UTC due timestamps and render them in Asia/Manila; null due dates stay undated. Keep all-day date strings separate from instants. Missing grades stay ungraded.
- Incremental updates only on endpoints with documented support; otherwise fetch pages and upsert by stable ID. Never infer deletion from an incomplete filtered result.
- Manual academic entry must remain available offline regardless of Canvas status.

No database binding or privileged token shipped to the PWA.                                     |

No provider selected and no resources created. Supabase is the initial evaluation candidate, not a completed integration or guarantee of perpetual free service.

Required before enabling sync: authenticated user ownership enforced server-side; HTTPS; transactional local outbox with operation IDs; incremental revision cursor; idempotent replay; atomic multi-record transfers; explicit conflicts on concurrent financial edits; tombstones for deletions; retry/reconnect tests; export and deletion flow; authorization tests with two isolated users. The existing single-document state must not be synchronized using blind last-write-wins. Prefer immutable financial events plus compensating corrections; existing mutable history requires a migration design before remote writes. Evaluate client encryption together with key recovery, never silently lose data if a key is lost.

Deployment and real credential connection require explicit user approval after implementation and review. Local-only operation remains the default. Background push remains a separate, unimplemented infrastructure feature.
